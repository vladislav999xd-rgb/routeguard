# RouteGuard — маршруты пациентов без потерянных шагов

RouteGuard — самостоятельный сервис для координации организационных маршрутов после получения медицинского заключения. Он объединяет сроки, записи, звонки, задачи и историю решений, показывает понятный приоритет и не даёт медицинских рекомендаций. Встроенное демо создаёт изолированное рабочее пространство с 20 воспроизводимыми сценариями.

> Статус: демонстрационный MVP, проходящий проверку перед показом заказчикам. Все данные синтетические. RouteGuard не является сертифицированным медицинским изделием и не предназначен для работы с реальными медицинскими данными без отдельной юридической, организационной и технической подготовки.

![Интерактивный 3D-лендинг RouteGuard](screenshots/landing-3d-desktop.png)

Ознакомительная страница — это семь связанных сцен от проблемы разрозненных действий до рабочего места координатора и безопасного демо. На desktop маршрут отображается процедурной Three.js-сценой: GSAP ScrollTrigger ведёт камеру по пространственной кривой, перестраивает карточки и раскрывает объёмные панели кабинета, звонка и аналитики. На мобильных устройствах и без WebGL используется HTML/CSS-представление; движение можно явно приостановить. Заголовок и CTA не зависят от загрузки 3D.

## Как устроено решение

```mermaid
flowchart LR
    U[Координатор] --> SPA[React / TypeScript]
    SPA --> API[Django REST API]
    API --> RULES[Транзакционные правила]
    RULES --> DB[(PostgreSQL 14)]
    API --> CALL[Помощник звонка]
    CALL --> TASKS[Задачи перезвона]
```

Пользователь открывает обзор, выбирает маршрут по объяснимому приоритету, связывается с пациентом или выбирает свободный слот, фиксирует результат и видит его в истории. Результат «Перезвонить» создаёт или обновляет одну открытую callback-задачу с датой и ответственным; повторная отправка контакта защищена `Idempotency-Key`.

## Возможности

- отдельные постоянные и гостевые рабочие пространства;
- 20 сценариев P001–P020 и восстановление демоданных;
- обзор, поиск, фильтры и объяснение приоритета;
- карточка маршрута со статусами, шагами, записями, документами и аудитом;
- правдивая многоэлементная история демосценариев и новых действий без подмены событий комментариями или документами;
- серверные ограничения: запись и выполнение доступны только активному маршруту, обязательные шаги выполняются последовательно;
- помощник звонка: цель, готовый текст, вопросы, предыдущий организационный контекст и структурированные результаты контактов;
- «Мои задачи», включая реальные задачи повторного звонка;
- одна открытая follow-up-задача после отмены/неявки с автоматическим закрытием после новой записи;
- безопасное бронирование: транзакция, блокировка, идемпотентность, запрет прошедших слотов и закрытие задачи повторной записи;
- snapshot-аналитика по маршрутам, просрочкам, неявкам, отменам и задачам с формулами в документации;
- адаптивный интерфейс для 390, 768, 1280 и 1440 px с карточкой пациента справа или поверх очереди;
- безопасные ответы API без вывода внутренних исключений.

## Пользовательский путь

```mermaid
flowchart TD
    A[Лендинг] --> B[Изолированное демо или вход]

    C --> D[Карточка маршрута]
    D --> E{Следующее действие}
    E -->|Связаться| F[Помощник звонка]
    F --> G[Результат / задача перезвона]
    E -->|Записать| H[Проверка и занятие слота]
    G --> I[История и следующий шаг]
    H --> I
```

## Быстрый локальный запуск

Требуются Python 3.11+ и Node.js 22+.

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements-dev.txt
python manage.py migrate
cd frontend
npm ci
npm run build
cd ..
python manage.py runserver
```

Откройте `http://127.0.0.1:8000/` и нажмите «Открыть демо». Локально без `DATABASE_URL` используется только техническая SQLite-база; production рассчитан на PostgreSQL.

## Навигация по репозиторию

| Путь | Назначение |
|---|---|
| `frontend/` | React 19, TypeScript, Vite, Three.js / React Three Fiber, e2e-тесты |
| `frontend/src/landing/` | семь DOM-сцен лендинга, scroll-driven WebGL-маршрут и адаптивный fallback |
| `core/` | модели, REST API, правила маршрутов, демосценарии и backend-тесты |
| `routeguard/` | конфигурация Django и WSGI |
| `backend_static/` | готовая production-сборка интерфейса |
| `docs/` | архитектура, сценарии, тестирование, миграция и размещение |
| `deploy/sprinthost/` | шаблоны точки входа для SprintHost |
| `scripts/build_release.ps1` | повторяемая сборка приватного архива для хостинга |

Сборщик также создаёт приватный `FIX/fix.php`: это однофайловый автоматический установщик и обновлятор для загрузки в `public_html/FIX/fix.php`. Он выполняет резервное копирование, развёртывание, установку Python-зависимостей, миграции, сборку статики и первичное создание владельца. В Windows весь SSH-деплой запускается двойным щелчком по `DEPLOY-TO-HOSTING.cmd`; архив отдельно переносить не требуется.

## Проверки

```bash
python manage.py check
python manage.py test
cd frontend
npm audit
npm run build
npx playwright test
```

Регрессионное покрытие включает 20 сценариев, правдивую многоэлементную историю, изоляцию рабочих пространств, последовательность обязательных шагов, защиту от дублей, стабильность `completed_at`, callback/follow-up-задачи, идемпотентность контактов и бронирования, формулы аналитики и сквозные браузерные пути. Фактические результаты конкретного прогона фиксируются отдельно; локальный SQLite не заменяет PostgreSQL-проверку конкурентных транзакций.
