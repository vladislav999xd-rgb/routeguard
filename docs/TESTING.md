# Тестирование

## Автоматические проверки

```bash
python manage.py check
python manage.py test core.tests -v 2
cd frontend
npm audit
npm run build
npx playwright test
```

Backend-тесты проверяют наличие P001–P020, изоляцию демосессий, отсутствие записи при GET, стабильность времён завершения, документ для закрытия шага, обязательную дату перезвона, callback-задачу, запрет прошедшего слота, идемпотентность и ограничения от дублей/двойного занятия.

Playwright проходит путь «лендинг → демо → обзор → поиск P016 → помощник звонка» в Microsoft Edge на viewport 390×844, 768×1024 и 1440×1000. Дополнительно проверяется отсутствие горизонтальной прокрутки всей страницы.

## PostgreSQL перед выпуском

SQLite используется только как быстрая локальная база. Перед production-выпуском прогоните тот же набор на PostgreSQL 14:

```bash
set DATABASE_URL=postgresql://user:password@localhost:5432/routeguard_test
python manage.py test
```

Тест параллельного бронирования должен выполняться именно на PostgreSQL: две независимые транзакции пытаются занять один слот, успешной остаётся ровно одна.

## Ручной smoke-check

1. Открыть гостевое демо и убедиться, что отображаются 20 маршрутов.
2. P001 подтвердить из черновика.
3. P002 записать в свободный будущий слот.
4. P012 добавить синтетическое подтверждение и проверить закрытие.
5. P016 сохранить «Перезвонить» с датой и увидеть задачу в «Мои задачи».
6. P015 убедиться, что повторный маршрут для того же исследования отклоняется.
7. Сбросить демо и проверить восстановление исходных состояний.
