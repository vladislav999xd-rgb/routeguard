# Развёртывание на SprintHost

## Требования

- PHP 8.2 или новее;
- PDO MySQL, mbstring, json и session;
- MySQL 5.7 или 8.0;
- Apache с поддержкой `.htaccess`;
- HTTPS для production-домена.

## 1. Подготовка базы и сайта

1. Создайте сайт или подпапку сайта в панели хостинга.
2. Создайте отдельную MySQL-базу и пользователя.
3. Сохраните хост, имя базы, имя пользователя и пароль.
4. Выберите совместимую версию PHP.

## 2. Конфигурация

Скопируйте `config.example.php` как `config.php` и заполните реквизиты. Для `install_token` и `maintenance_token` используйте две разные случайные строки длиной не менее 24 символов.

`config.php` нельзя коммитить, отправлять в публичные каналы или включать в универсальный архив репозитория. Если хостинг позволяет, храните файл выше `public_html` и задайте путь переменной окружения `ROUTEGUARD_CONFIG`.

## 3. Загрузка

1. Загрузите файлы приложения в `public_html` или корень выбранного домена.
2. Убедитесь, что `.htaccess` загружен.
3. Добавьте подготовленный `config.php` непосредственно на сервере.
4. Проверьте права PHP на чтение конфигурации и запись установочного lock-файла.

Архивы, дампы и резервные копии не следует постоянно хранить в публичном каталоге.

## 4. Установка

1. Откройте `https://example.com/install.php`.
2. Введите одноразовый install token.
3. Проверьте параметры подключения к БД.
4. Для установки в корень оставьте `BASE_URL` пустым; для подпапки укажите путь вида `/routeguard`.
5. Создайте владельца с уникальным паролем не короче 12 символов.

Установщик создаёт только таблицы с выбранным префиксом. После успешной установки повторный запуск блокируется.

## 5. Проверка после запуска

1. Главная страница и вход отвечают без PHP-ошибок.
2. Прямой доступ к `config.php`, `schema.sql`, `app/` и `storage/` запрещён.
3. Новая демосессия содержит 20 синтетических пациентов.
4. P006 позволяет открыть помощника, сохранить результат звонка и выбрать новый слот.
5. В консоли браузера нет ошибок.
6. На ширинах 1440, 1024 и 390 px отсутствует горизонтальная прокрутка всей страницы.

## 6. Обновления через FIX

Перед обновлением экспортируйте таблицы приложения и скачайте текущие файлы. Затем загрузите новую версию `FIX/fix.php` и выполните:

```bash
php FIX/fix.php
```

Либо временно запустите файл по HTTPS:

```text
https://example.com/FIX/fix.php?token=MAINTENANCE_TOKEN
```

После веб-запуска удалите `FIX/fix.php` с production-сервера до следующего обновления. Созданные обновлятором резервные копии закрываются от прямого HTTP-доступа, но их всё равно следует скачать и удалить после проверки.

## 7. Эксплуатационная безопасность

- храните production-секреты вне Git;
- не используйте синтетический прототип для реальных медицинских данных;
- включите автоматические резервные копии;
- регулярно удаляйте просроченные демосессии;
- меняйте токены и пароль после возможной утечки;
- оставляйте HTTPS включённым постоянно.
