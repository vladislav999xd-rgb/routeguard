# Развёртывание Python-версии RouteGuard

Подробная пошаговая инструкция находится в [DEPLOYMENT_SPRINTHOST.md](DEPLOYMENT_SPRINTHOST.md). Этот документ фиксирует действующую архитектуру и обязательные ограничения обновления.

## Фактическая production-схема

- Django 5.2 работает через WSGI под Apache/uWSGI SprintHost X-4.
- Код приложения расположен вне публичного каталога: `~/domains/<domain>/routeguard_app`.
- `public_html/site.wsgi` подключает приложение и его `.venv`.
- React заранее собирается локально; Node.js на сервере не требуется.
- Статические файлы размещаются в `public_html/static`.
- Production использует PostgreSQL через приватный `routeguard_app/.env`.

Удалённый `main` с PHP-кодом не является источником deployment для Python-версии.

## Сборка релиза

Приватная сборка создаётся локально:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_release.ps1 `
  -DatabaseName ИМЯ_БАЗЫ `
  -DatabaseUser ПОЛЬЗОВАТЕЛЬ `
  -DatabasePassword ПАРОЛЬ
```

Повторная локальная сборка может использовать сохранённое приватное окружение с `-ReuseExistingEnvironment`. Результаты `FIX/fix.php`, `release/` и архив исключены из Git.

## Обязательные проверки до загрузки

1. Выполнить backend-тесты, migration check, frontend typecheck/build и доступные Playwright-тесты.
2. Сделать дамп PostgreSQL и копию текущих `routeguard_app` и `public_html`.
3. Проверить, что в Git не попали `.env`, FIX-токен, архив, SSH-ключи и данные владельца.
4. Проверить релиз на отдельной базе или временном домене, если инфраструктура это позволяет.
5. Получить отдельное разрешение владельца на production deployment.

## Установка и обновление

`DEPLOY-TO-HOSTING.cmd` загружает приватный `FIX/fix.php` по SSH и запускает его. SprintHost может потребовать пароль и одноразовый код. Автоматическое выполнение этого шага агентами запрещено без явного разрешения.

Установщик создаёт файловую резервную копию, разворачивает payload, сохраняет существующий `.env`, обновляет виртуальное окружение, применяет Django migrations, собирает статику, выполняет bootstrap и `check --deploy`, затем перезапускает WSGI.

## Известные ограничения текущего установщика

- Файловые backups и сам installer размещаются под `public_html/FIX`; они защищены `.htaccess` и правами, но безопаснее переносить их вне публичного дерева.
- Переключение файлов не полностью атомарно: ошибка `pip`, migration или production-check требует ручного восстановления.
- Дамп БД не создаётся автоматически.
- Откат migration должен оцениваться для каждого изменения схемы отдельно.

До устранения этих ограничений production-обновление выполняется только при наличии проверенной резервной копии и окна восстановления.

## Проверка после установки

- `/api/health/` возвращает успешный JSON;
- открываются главная страница и `/app`;
- гостевое демо создаёт изолированный workspace;
- мутации маршрута, история, задачи и аналитика проходят smoke-сценарий;
- `.env`, `routeguard_app`, `OWNER-CREDENTIALS.txt` и `FIX` недоступны через HTTP;
- в браузере нет ошибок JavaScript/API.

## Откат

При ошибке остановить дальнейшие мутации, сохранить журналы, восстановить предыдущие `public_html` и `routeguard_app`, затем восстановить совместимый дамп PostgreSQL. Полный порядок и границы миграции описаны в [MIGRATION.md](MIGRATION.md).
