# Миграция и откат

## Переход с PHP-прототипа

1. До переключения экспортировать MySQL и скачать прежние файлы.
2. Развернуть v2 рядом с текущим `public_html`, подключить отдельную PostgreSQL 14 базу.
3. Выполнить миграции и создать постоянное пространство/администратора.
4. Прогнать smoke-check на временном домене.
5. Переключить WSGI-точку входа и HTTPS только после приёмки.

Прямой автоматический импорт реальных медицинских данных намеренно не включён: схемы отличаются, а источник требует отдельного отображения полей, журнала расхождений и юридической проверки. Старые файлы не удаляются до подтверждения v2.

## Откат

1. Перевести сайт в режим обслуживания.
2. Вернуть предыдущую папку `public_html` из резервной копии.
3. Вернуть предыдущую конфигурацию домена/PHP.
4. Не удалять PostgreSQL v2 до разбора изменений; сохранить дамп.
5. Проверить вход, маршруты и одну безопасную тестовую операцию в старой версии.

Обновление v2 выполняется архивом только после дампа PostgreSQL и копии каталога приложения. Миграции Django применяются перед переключением трафика; необратимые миграции должны сопровождаться отдельным планом восстановления.
