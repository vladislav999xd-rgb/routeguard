| P005 | Завершённый маршрут | Только просмотр | Дата завершения остаётся неизменной |
| P006 | Отмена пациентом | Звонок, новая запись | Маршрут возвращается в обычную работу |
| P007 | Неявка | Создать контакт/задачу, перезаписать | Появляется задача и новая запись после подтверждения |
| P008 | Нет слота до срока | Согласовать альтернативу | Выбран поздний слот или другая площадка |

| P010 | Неполное синтетическое заключение | Подтвердить/уточнить план | Маршрут остаётся организационным, без клинических выводов |
| P011 | Нет ответственного | Назначить сотрудника | Маршрут связан с Employee, предупреждение снято |
| P012 | Этап выполнен без подтверждения | Добавить демодокумент | После подтверждения маршрут может завершиться |

| P017 | Приём отменён клиникой | Звонок, перезапись | Причина возврата сохранена, выбран новый слот |

| P019 | Два этапа завершены | Просмотр истории | Маршрут закрыт, даты завершения стабильны |
| P020 | Срок наступает завтра | Обработать приоритет | Видна причина «срок приближается», создаётся запись/задача |

## Подтверждённые недостатки исходного кода

1. Чтение обзора и очереди вызывает массовый пересчёт с `UPDATE`.
2. Защита дубликата явно привязана к коду P015.
3. Вход владельца каждый раз создаёт новый демо-workspace.
4. Ответственные хранятся строками и проверяются по двум зашитым именам.
5. Повторный звонок не создаёт задачу.
6. Бронирование не отвергает прошедший слот.
7. Ошибка верхнего уровня напрямую показывается пользователю.
8. Ограничения активной записи этапа и слота обеспечены не полностью на уровне БД.
9. `completed_at` маршрута может перезаписываться повторным пересчётом.
10. В актуальном интерфейсе и метаданных остались упоминания прежнего бренда.

1. Создать Django-модель данных, сервисы переходов и REST API.
2. Перенести все 20 сценариев и добавить тесты правил/изоляции.
3. Создать React-интерфейс и самостоятельную визуальную систему RouteGuard.
4. Собрать frontend в статику Django и проверить основные пути в браузере.
5. Подготовить миграцию, deploy/rollback, CI, документацию и release-архив.

Исходная PHP-реализация остаётся в репозитории до завершения проверки v2 и не используется как источник production-миграций.
